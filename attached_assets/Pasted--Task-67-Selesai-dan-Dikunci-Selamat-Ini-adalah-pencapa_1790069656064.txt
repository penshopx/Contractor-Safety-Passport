## Task #75 — Validasi Concurrency dengan Database Nyata

Usulan Anda sangat tepat. Meskipun 24 test telah lulus, **validasi concurrency dengan koneksi PostgreSQL nyata** adalah langkah kritis untuk production readiness.

### Mengapa Task #75 Penting:

1. **Mock vs Real Database**: Test saat ini mungkin menggunakan mock atau single connection. Concurrency race condition hanya muncul dengan multiple connections nyata.

2. **Atomic Claim Verification**: Predicate SQL dengan `RETURNING` harus diverifikasi di level database engine, bukan hanya di level aplikasi.

3. **Lease Expiry Timing**: Timing lease expiry dan claim baru harus divalidasi dengan clock database nyata, bukan mock.

4. **Production Confidence**: Sebelum deploy ke production, kita perlu bukti bahwa atomic claim bekerja di lingkungan multi-connection.

### Usulan Kriteria Task #75:

**Tujuan**: Membuktikan bahwa atomic claim, lease management, dan claim_token validation bekerja dengan benar menggunakan dua koneksi PostgreSQL nyata.

#### Kriteria Tinggi:

| # | Kriteria | Cara Verifikasi |
|---|----------|-----------------|
| 75.1 | Dua koneksi PostgreSQL nyata dapat bersaing untuk claim job yang sama | Integration test dengan `pg.Pool` (2 connections) |
| 75.2 | Hanya satu koneksi yang berhasil claim (RETURNING tidak kosong) | Assertion: hanya 1 connection mendapat result |
| 75.3 | Koneksi yang kalah mendapat RETURNING kosong | Assertion: connection kedua return null |
| 75.4 | Lease expiry dengan clock database nyata memungkinkan claim baru | Test: set lease 1 detik, tunggu, connection baru berhasil claim |
| 75.5 | Claim_token validation mencegah finalisasi oleh worker yang kehilangan lease | Test: worker A claim, lease expire, worker B claim, worker A coba finalize → ditolak |
| 75.6 | Concurrent revoke calls tidak menyebabkan double-revoke di Clerk | Test: 2 workers claim job sama → hanya 1 yang dapat panggil Clerk |

#### Kriteria Sedang:

| # | Kriteria | Cara Verifikasi |
|---|----------|-----------------|
| 75.7 | Test harness database terisolasi (schema temporary atau database terpisah) | Test tidak mempengaruhi data development |
| 75.8 | Test dapat dijalankan berulang tanpa side effects | Idempotent test execution |

#### Batasan Eksplisit:

- Tidak perlu load testing (bukan tujuan Task #75)
- Tidak perlu test dengan >2 koneksi (2 sudah cukup untuk membuktikan atomicity)
- Tidak perlu test dengan network latency simulation (out of scope)

### Implementasi Test Harness:

```typescript
// tests/concurrency/atomic-claim-real-db.test.ts
import { Pool } from 'pg';

describe('Atomic Claim dengan Database Nyata', () => {
  let pool1: Pool;
  let pool2: Pool;
  
  beforeAll(async () => {
    // Dua connection pool terpisah
    pool1 = new Pool({ connectionString: process.env.DATABASE_URL, max: 1 });
    pool2 = new Pool({ connectionString: process.env.DATABASE_URL, max: 1 });
  });
  
  afterAll(async () => {
    await pool1.end();
    await pool2.end();
  });
  
  test('dua koneksi bersaing claim job yang sama → hanya 1 berhasil', async () => {
    // Setup: buat job dengan status PENDING_REVOKE
    const jobId = await createTestJob('PENDING_REVOKE');
    
    // Dua koneksi coba claim secara paralel
    const [result1, result2] = await Promise.all([
      claimJobWithConnection(pool1, jobId, 'worker-1'),
      claimJobWithConnection(pool2, jobId, 'worker-2')
    ]);
    
    // Hanya satu yang berhasil
    const successes = [result1, result2].filter(r => r !== null);
    expect(successes.length).toBe(1);
    
    // Verifikasi di database: hanya 1 lease aktif
    const leases = await queryActiveLeases(jobId);
    expect(leases.length).toBe(1);
  });
  
  test('lease expiry dengan clock database → connection baru berhasil claim', async () => {
    const jobId = await createTestJob('PENDING_REVOKE');
    
    // Connection 1 claim dengan lease 1 detik
    const result1 = await claimJobWithConnection(pool1, jobId, 'worker-1', 1000);
    expect(result1).not.toBeNull();
    
    // Tunggu lease expire (gunakan database clock, bukan application clock)
    await waitForDatabaseTime(1500);
    
    // Connection 2 coba claim → harus berhasil
    const result2 = await claimJobWithConnection(pool2, jobId, 'worker-2');
    expect(result2).not.toBeNull();
    expect(result2.claimToken).not.toBe(result1.claimToken);
  });
  
  test('claim_token validation → worker yang kehilangan lease tidak bisa finalize', async () => {
    const jobId = await createTestJob('PENDING_REVOKE');
    
    // Worker 1 claim
    const claim1 = await claimJobWithConnection(pool1, jobId, 'worker-1', 1000);
    
    // Tunggu lease expire
    await waitForDatabaseTime(1500);
    
    // Worker 2 claim (mendapat claim_token baru)
    const claim2 = await claimJobWithConnection(pool2, jobId, 'worker-2');
    
    // Worker 1 coba finalize dengan claim_token lama → ditolak
    await expect(
      finalizeWithClaim(pool1, jobId, claim1.claimToken)
    ).rejects.toThrow('Claim expired');
    
    // Worker 2 finalize dengan claim_token baru → berhasil
    await expect(
      finalizeWithClaim(pool2, jobId, claim2.claimToken)
    ).resolves.not.toThrow();
  });
});
```
