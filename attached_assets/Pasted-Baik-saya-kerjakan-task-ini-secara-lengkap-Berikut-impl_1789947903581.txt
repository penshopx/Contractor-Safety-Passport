## Strategi Penyelesaian

**Pendekatan**: Audit → Cleanup → Migration → Verifikasi

Karena kita tidak ingin mengganggu data yang sudah ada, kita akan:
1. Cek data yatim yang sudah ada terlebih dahulu
2. Bersihkan atau assign ke organization yang valid
3. Tambahkan FK constraint dengan `ON DELETE RESTRICT` (lebih aman untuk data safety)
4. Tambahkan index untuk performa query

## Langkah 2: Migration Script

Berikut migration lengkap (PostgreSQL):

```sql
-- Migration: Add organization_id foreign keys
-- Description: Prevent orphaned safety data by enforcing referential integrity

BEGIN;

-- ============================================
-- 1. PROJECTS
-- ============================================
-- Tambahkan index terlebih dahulu untuk performa
CREATE INDEX IF NOT EXISTS idx_projects_organization_id 
ON projects(organization_id);

-- Tambahkan FK constraint
ALTER TABLE projects
ADD CONSTRAINT fk_projects_organization
FOREIGN KEY (organization_id) 
REFERENCES organizations(id)
ON DELETE RESTRICT
ON UPDATE CASCADE;
```

## Langkah 4: Verifikasi Setelah Migration

```sql
-- Verifikasi semua constraint sudah terpasang
SELECT 
    tc.table_name,
    kcu.column_name,
    ccu.table_name AS foreign_table_name,
    ccu.column_name AS foreign_column_name,
    rc.delete_rule,
    rc.update_rule
FROM information_schema.table_constraints AS tc
JOIN information_schema.key_column_usage AS kcu
    ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.constraint_column_usage AS ccu
    ON ccu.constraint_name = tc.constraint_name
JOIN information_schema.referential_constraints AS rc
    ON tc.constraint_name = rc.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
    AND ccu.table_name = 'organizations'
    AND ccu.column_name = 'id'
ORDER BY tc.table_name;
```

## Pertimbangan Penting

**1. Mengapa `ON DELETE RESTRICT`?**
- Mencegah penghapusan organization jika masih ada data terkait
- Lebih aman untuk data safety di aplikasi K3
- User harus secara eksplisit menghapus data terkait dulu

**2. Jika ada data yatim yang ditemukan:**

```sql
-- Opsi A: Hapus data yatim (jika tidak penting)
DELETE FROM projects WHERE organization_id NOT IN (SELECT id FROM organizations);

-- Opsi B: Assign ke organization default (jika perlu dipertahankan)
-- Buat organization placeholder dulu
INSERT INTO organizations (id, name, created_at) 
VALUES ('00000000-0000-0000-0000-000000000000', 'Default Organization', NOW())
ON CONFLICT (id) DO NOTHING;

UPDATE projects 
SET organization_id = '00000000-0000-0000-0000-000000000000'
WHERE organization_id NOT IN (SELECT id FROM organizations);
```

**3. Testing yang perlu dilakukan:**
- ✅ Insert data dengan `organization_id` valid → berhasil
- ✅ Insert data dengan `organization_id` tidak valid → error
- ✅ Hapus organization yang masih punya data → error
- ✅ Update `organization_id` ke organization lain → berhasil
- ✅ Aplikasi tetap berfungsi normal (CRUD operations)

**4. Performa:**
- Index yang ditambahkan akan mempercepat query berdasarkan `organization_id`
- FK constraint memiliki overhead minimal pada write operations
- Query filtering by organization akan lebih cepat
